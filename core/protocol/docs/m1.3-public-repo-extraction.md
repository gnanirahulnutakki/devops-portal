## Purpose

The `core/` subtree currently lives inside the larger `devops-portal` repo. For
the protocol to be a CNCF-trackable thing, it must:

1. Live in its own repo under a vendor-neutral GitHub organization
2. Have its full git history preserved (subtree-split, not a fresh init)
3. Be renamed from the `TBD_PROJECT_NAME` placeholder to the working name
   `opspact` per [M1.2](m1.2-name-decision.md)
4. Carry CNCF-grade governance scaffolding (already drafted in `core/*.md`)
5. Have a public README that orients an external reviewer in <5 minutes

This document specifies how to do all five in one atomic operation.

## Decision needed from the operator

Pick a GitHub organization. Three candidates, in order of escalating commitment:

| Option | Path | Cost | When |
|---|---|---|---|
| **A. Personal** | `github.com/gnanirahulnutakki/opspact` | $0 | Immediately |
| **B. New vendor-neutral org** | `github.com/opspact-dev/opspact` | $0 (free tier OK for OSS) | ~10 min to set up |
| **C. CNCF Sandbox host** | `github.com/cncf/opspact` | requires CNCF acceptance — out of M1 scope | M4+ |

**Recommendation**: B. A new GitHub org named `opspact-dev` (or `opspact-io`,
`opspact-foundation`, etc.) signals vendor-neutrality from day one — even
though a single maintainer holds it for now. Migrating from a personal org
to a CNCF-foundation org later is a one-PR transfer; migrating *from* a
personal org carries a "hosted on personal account" stigma that hurts the
TAG-AI submission.

If the operator does not want to create the org yet, this work can land as
a **draft PR** against the personal account in option A, with the explicit
note "this PR will be merged after the org transfer in M3-M4."

The rename is mechanical: all `TBD_PROJECT_NAME` (uppercase, used as
identifier in Go imports + generic placeholders) become `opspact`; all
`tbd_project_name` (lowercase, used in proto package name) become
`opspact`.

**Edge cases the script must handle**:
- Go import paths: `github.com/TBD_PROJECT_NAME/core/...` → `github.com/<org>/opspact/...` — the `<org>` part comes from the operator decision
- Proto package: `tbd_project_name.action.v0` → `opspact.action.v0`
- proto `option go_package`: `github.com/TBD_PROJECT_NAME/go/action/v0;actionv0` → `github.com/<org>/opspact/go/action/v0;actionv0`
- Schema URI examples in `schema-distribution.md`: `https://schemas.TBD_PROJECT_NAME.dev/...` → `https://schemas.opspact.dev/...`

## Subtree split — exact commands

After the org decision is made, the subtree-split is one git command on
the existing repo (run from the **devops-portal repo root**, on a clean
working tree):

```bash
# 1. Decide the target org and repo name
TARGET_ORG=opspact-dev          # or whatever was decided
TARGET_REPO=opspact

# 2. Create the new GitHub repo (one-time, manual step in the GitHub UI):
#    https://github.com/organizations/$TARGET_ORG/repositories/new
#    - Name: opspact
#    - Description: "Multi-Cluster MCP Federation Protocol"
#    - Visibility: Public
#    - Initialize: NO (no README, no license, no .gitignore — we bring our own)
#    - License: Apache 2.0 (selectable in repo settings, applies to existing files)

# 3. Subtree-split the core/ directory preserving history
git subtree split --prefix=core --branch opspact-extracted

# 4. Push the extracted branch as `main` of the new repo
git remote add opspact-origin git@github.com:$TARGET_ORG/$TARGET_REPO.git
git push opspact-origin opspact-extracted:main

# 5. Verify the new repo has the right history
#    (visit https://github.com/$TARGET_ORG/$TARGET_REPO and check commit count
#    matches the local-side `git log --oneline opspact-extracted | wc -l`)

# 6. Clean up the local extraction branch
git branch -D opspact-extracted
git remote remove opspact-origin
```

After step 4, the new repo has every commit that ever touched `core/`,
with all paths rebased to the repo root (no more `core/` prefix).

## Atomic rename PR — automated script

The rename can run on either side: against the `devops-portal` repo's
`core/` subdir BEFORE the subtree split, or against the new `opspact` repo
AFTER the split. **Do it AFTER the split** so the devops-portal repo
keeps the `TBD_PROJECT_NAME` placeholder intact (the next subtree-pull
sync would un-rename it otherwise).

Script: `core/deploy/scripts/m1.3-rename.sh` (committed in this PR;
runs against the new repo's root after extraction).

```bash
#!/bin/bash
# m1.3-rename.sh — one-shot atomic rename from TBD_PROJECT_NAME to opspact
# Run from the new opspact repo root, on a clean branch.
# Usage: ./m1.3-rename.sh <github-org-name>
#   e.g.:  ./m1.3-rename.sh opspact-dev

set -euo pipefail

if [ "$#" -ne 1 ]; then
  echo "Usage: $0 <github-org-name>"
  exit 1
fi

ORG="$1"

# Refuse to run on a dirty working tree
if [ -n "$(git status --porcelain)" ]; then
  echo "ERROR: working tree is dirty; commit or stash first"
  exit 1
fi

# Refuse to run on a branch named main / master (work on a branch)
BRANCH=$(git rev-parse --abbrev-ref HEAD)
if [ "$BRANCH" = "main" ] || [ "$BRANCH" = "master" ]; then
  echo "ERROR: refusing to rename on $BRANCH; checkout a feature branch first"
  exit 1
fi

# Pass 1: replace uppercase TBD_PROJECT_NAME (used in Go imports, headings, etc.)
git ls-files | xargs grep -l "TBD_PROJECT_NAME" | while read -r f; do
  sed -i.bak "s|github.com/TBD_PROJECT_NAME/|github.com/${ORG}/|g; s|TBD_PROJECT_NAME|opspact|g" "$f"
  rm "$f.bak"
done

# Pass 2: replace lowercase tbd_project_name (used in proto package names + URLs)
git ls-files | xargs grep -l "tbd_project_name" | while read -r f; do
  sed -i.bak "s|tbd_project_name|opspact|g" "$f"
  rm "$f.bak"
done

# Pass 3: rename go.mod's module path
if grep -q "module github.com/opspact/" go.mod 2>/dev/null; then
  sed -i.bak "s|module github.com/opspact/core|module github.com/${ORG}/opspact|" go.mod
  rm go.mod.bak
fi

# Verify nothing TBD remains
remaining=$(git ls-files | xargs grep -l "TBD_PROJECT_NAME\|tbd_project_name" 2>/dev/null || true)
if [ -n "$remaining" ]; then
  echo "WARNING: TBD_PROJECT_NAME still present in:"
  echo "$remaining"
  exit 1
fi

# Run gofmt to clean up any whitespace artifacts
if command -v gofmt > /dev/null; then
  gofmt -w .
fi

# Build to confirm imports resolve
if command -v go > /dev/null; then
  go mod tidy
  go build ./... || (echo "ERROR: build failed after rename" && exit 1)
fi

echo "Rename complete. Review with: git diff"
echo "Commit with: git commit -am 'rename: TBD_PROJECT_NAME -> opspact (M1.3)'"
```

## Risk register

- **Risk: rename script misses an edge case.** Mitigation: the script's
  final pass uses `git grep` to fail loud if `TBD_PROJECT_NAME` still
  appears anywhere. Build verification catches semantic breakage.
- **Risk: subtree-split history corrupts.** Mitigation: git subtree split
  is read-only against the source repo; failure is rerunnable. Verify
  commit count matches before publishing.
- **Risk: GitHub org name conflict.** Mitigation: M1.2 validated `opspact`
  is clear of conflicts but not the org name. If `opspact-dev` is taken,
  fall back to `opspact-io`, `opspact-foundation`, or
  `opspact-protocol` in priority order.
- **Risk: someone else creates a github.com/X/opspact repo before us.**
  Mitigation: low-stakes — we own the name as a working name; a
  collision repo creates noise but doesn't block our use.
