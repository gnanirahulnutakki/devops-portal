# M1.2 — Name Decision

**Decision: `opspact`** (working name pending formal IP clearance before any
product launch). Chosen 2026-04-25.

## Decision summary

| | |
|---|---|
| **Selected name** | `opspact` |
| **Pronunciation** | "ops-pact" — /ɒps pækt/ |
| **Etymology** | "ops" (operations, the protocol's domain) + "pact" (agreement, treaty — captures the federation envelope's role as a typed agreement between clusters) |

| `verdict` | **Eliminated** | [`verdict` exists on PyPI](https://pypi.org/project/verdict/) — recently-active LLM-as-judge framework, would be confusing in AI/agentic space |
| `beacon` | **Eliminated** | Generic term in observability, IoT/Bluetooth space. Multiple PyPI projects (`graphite_beacon`, `beacontools`, etc.). Hard to differentiate, hard to win SEO |
| `signet` | **Eliminated** | Already used in security/signing domain (Sigstore-adjacent terminology); risk of confusion in supply-chain-security space |

| **`opspact`** | **SELECTED** | Coined; no PyPI, npm, or GitHub hit; no CNCF/CNCF-adjacent project conflict; no public USPTO trademark hit; pronounceable; descriptive ("ops" + "pact" captures domain + value); short enough to be memorable |

## Why opspact, beyond elimination

1. **Coined word**: low collision probability, high distinctiveness for trademark purposes.
2. **Domain-aligned**: "ops" is unambiguous for cloud-native operators; "pact" suggests agreement / contract / treaty — matches the protocol's role as a typed envelope carrying agreed-upon semantics across cluster boundaries.
3. **Not overloaded**: avoids the confusion of names that already mean something specific in adjacent ecosystems (signet/attest in supply-chain security, beacon in observability/IoT, verdict in LLM evals).
4. **Pronounceable**: consonant cluster `psp` is unusual in English but not difficult; "ops-pact" reads naturally.
5. **Short**: 7 letters; memorable; works as both a project and a binary name.

## What this decision does NOT cover

- **Formal trademark clearance**: a paid IP search (Markify, Corsearch, or law-firm engagement) is required before any product launch or trademark registration. **Cost: ~$500-1500 for a US-only knockout search; ~$3000+ for a comprehensive multi-jurisdiction clearance.** Out of scope for this RFC.
- **International registration**: if the project achieves CNCF Incubating status, the Linux Foundation handles trademark assignment and may register the mark. The candidate has not been cleared in EU, UK, Japan, China, etc.
- **Domain registration**: `opspact.dev` and `opspact.io` registration deferred until M1.3 (public repo) decision is made.
- **Community signal check**: a single Twitter/Mastodon/Bluesky post asking "does anyone object to / know of conflicts with `opspact`?" is recommended before the public M1.3 announcement. Tracked separately.

## Risk register

- **Risk: a future formal IP search turns up a conflict.** Mitigation: this is a v0.1 working name; the rename burden is bounded (string replace + import path update). If a conflict surfaces before CNCF submission, restart the elimination process from this document.
- **Risk: the name doesn't resonate with the community.** Mitigation: the name is functional, not aspirational. If the M3 design partners + co-maintainers all push back, the rename burden is still finite. Don't optimize for "marketing perfect" before the protocol has shipped.
- **Risk: someone files a trademark on `opspact` between this decision and M1.3.** Mitigation: M1.3 (public repo) should follow within weeks, not months. Filing a defensive trademark application is M2 work if Linux Foundation isn't yet handling it.
