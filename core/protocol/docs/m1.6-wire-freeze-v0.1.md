# M1.6 — v0.1 Wire Freeze

**Status**: candidate — 2026-04-25
**Author**: gnanirahulnutakki (mechanical assist: codex)
**Replaces**: pre-rewrite `action-protocol.proto` (the file with the
2026-04-11 deprecation notice listing 5 known issues)

## What this delivers

The wire-level proto — `core/protocol/action-protocol.proto` — has been
rewritten to address all 5 issues called out in the deprecation notice
of the previous draft, plus to land the three documented decisions
(D8, D14, D16) that were specified but not yet on the wire.

`protoc` compiles the new proto to a clean descriptor set (8.4 KB).
`buf lint` reports only pre-existing stylistic warnings (filename
casing, package directory layout, naming suffix conventions) — no
new lint issues were introduced. None of the lint warnings reflect
correctness bugs.

## Decisions applied

| Decision | What landed in v0.1 wire |
|---|---|
| **D1 — Schema-addressed opaque payload** | `OperationRequest` now carries `schema_uri` (string) + `payload_digest` (bytes, SHA-256) + `payload` (bytes). `google.protobuf.Struct` removed entirely. Same shape applies to `OperationProgress.summary_payload` and `OperationResult.output_payload` |
| **D2 — Lease as authoritative liveness; in-band keepalive for streams** | `Heartbeat` renamed to `StreamKeepalive`; carries only stream-scoped liveness (observed_at, cert_expires_at, inflight_operations, policy_hash). The Kubernetes Lease object remains authoritative for cluster-level liveness |
| **D3 — Wire-version negotiation** | `AgentHello.protocol_version` (current), `AgentHello.supported_protocol_versions` (negotiation set), `AgentHello.supported_features` (capability flags) |
| **D5 — Gateway-authored canonical audit** | `AuditEvent` removed from `AgentEnvelope.payload` oneof. Field 16 reserved to prevent accidental reuse. The message itself is kept for use by the gateway's audit-storage layer (the gateway synthesizes `AuditEvent` from `OperationAck`/`OperationProgress`/`OperationResult` server-side) |
| **D8 — Credential references** | New `CredentialReference` message (`credential_uri`, `credential_version`, `provider`, `required_scope`). Carried in both `AdapterCapability.credential_references` and `OperationRequest.credential_references` |
| **D14 — Concurrency / lock scopes** | New `LockScope` enum (`UNSPECIFIED`, `NONE`, `TARGET`, `GROUP`, `ADAPTER`) on `AdapterCapability.lock_scope`. New `OperationRequest.target_uri` for conflict detection |
| **D16 — Schema distribution discovery** | `AgentHello.supported_schemas` (repeated string) lets the gateway reject calls before dispatch when the agent does not claim to handle the request's `schema_uri` |

## Backpressure (originally issue #5 in the deprecation notice)

`AgentHello.max_concurrent_ops` (uint32) advertises the agent's bounded
queue depth. The gateway is expected to honor this as a soft limit —
new dispatches return `OPERATION_STATE_REJECTED` (or are deferred per
the gateway's queue policy) when the agent's reported `inflight_operations`
in the most recent `StreamKeepalive` is at or above this value.

Windowed flow tokens (the more sophisticated flow-control mechanism we
considered) are deferred to v0.2+ per the original issue scoping.

## Notable structural changes from the previous draft

These weren't required by the issue list but are improvements introduced
during the rewrite:

1. **Service renamed `AgentGateway` → `ActionProtocol`**. The old name
   conflated the protocol with one component (the gateway); the new name
   names the wire contract itself, which is what client/server
   implementations bind to.
2. **`AgentEnvelope.nonce` typed as `bytes` instead of `uint64`**.
   Random bytes are stronger replay protection than monotonic counters
   when paired with the gateway's nonce-cache window (a counter forces
   the gateway to remember the high-water mark per agent forever; a
   bytes-nonce just needs a recent-history cache).
3. **`AgentEnvelope` and `ControlEnvelope` add `stream_id`, `sequence`,
   and `key_id`**. The `key_id` field supports key rotation without
   breaking in-flight signatures (the verifier looks up the public key
   by `key_id` rather than relying on a single per-agent key).
4. **`CapabilityAdvertisement` message removed**. Capabilities are now
   inlined into `AgentHello.capabilities` (repeated `AdapterCapability`).
   The protocol still supports re-announcing capabilities — the agent
   simply opens a new stream and sends a fresh `AgentHello`.
5. **New `AgentGoodbye` message** for graceful disconnect. Carries
   `reason`, `retryable` flag, suggested `ReconnectBehavior`, and
   `retry_after`. Unblocks orderly drain semantics.
6. **`OperationState` replaces `UNKNOWN` with explicit `REJECTED` and
   `TIMED_OUT`**. Reduces ambiguity in audit logs — distinguishes "we
   don't know" from "we know it failed for one of these specific
   reasons."

## What did NOT change

Per the M1.6 contract:
- proto3 syntax
- The two RPCs: `Connect` (bidi stream) and `Enroll` (unary)
- The `OperationCancel`, `PolicyUpdate`, `RevocationNotice`, `HealthCheck`
  control messages
- The `PolicyVerdict` message
- The `EnrollRequest` and `EnrollResponse` messages
- The package name `tbd_project_name.action.v0` (will become
  `opspact.action.v0` in M1.3 atomic rename)
- The go_package option (will be updated in M1.3 atomic rename)
- Use of `google.protobuf.Timestamp` and `google.protobuf.Duration`
- The general envelope-and-payload pattern

## What did NOT make it into v0.1

These are deferred to v0.2 by design:

- Windowed flow control (only soft `max_concurrent_ops` advertisement
  in v0.1)
- The streaming adapter operation class (`ADAPTER_OPERATION_CLASS_STREAM`
  is replaced by the more general approach of carrying the stream
  protocol in the operation's `schema_uri` — e.g.,
  `mcp://tools/call/streaming/v1.0`)
- Capability discovery beyond what's in `AgentHello` (no separate
  `Discover` RPC)
- Multi-tenancy fields (D17 — separate decision, separate rev)
- OAuth resource-server-style scope challenge responses on the protocol
  (Vault and OAuth integrations live in CAProvider / D8 layers)
- Native log/metric forwarding messages (the protocol carries operations,
  not telemetry)

## Sign-off

This is a v0.1 freeze candidate. The maintainer's commitment is: from
this commit forward, breaking changes to the `action-protocol.proto`
require a corresponding bump in `protocol_version` AND a migration note
in `CHANGELOG.md`. Field-additive evolution under the same
`protocol_version` is permitted (proto3 allows it); field renumbering
or type changes are not.
