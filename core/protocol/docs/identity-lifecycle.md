Identity is not an implementation detail in this protocol. The protocol is only safe if enrollment, rotation, revocation, and replay protection are explicit and testable. The reference pattern is Open Cluster Management’s `ManagedCluster` registration flow, which uses short-lived bootstrap credentials, CSR approval, and hub-side acceptance rather than implicit trust ([ManagedCluster registration](https://open-cluster-management.io/docs/concepts/cluster-inventory/managedcluster/)).

The bootstrap primitive is the join token. It is issued out of band by the gateway CLI or admin API and contains four required attributes: `token_id`, `cluster_hint`, `expires_at`, and `single_use`. The default TTL is one hour. The token is intentionally weak compared with the long-lived client certificate that follows; it is only powerful enough to request enrollment. It must be auditable, revocable before use, and unusable after first successful consumption.

The CSR flow is agent-driven. The agent generates its own keypair locally and never exports the private key. It calls `AgentGateway.Enroll`, presenting the join token, a PEM-encoded CSR, and an `agent_fingerprint` derived from the public key. The gateway validates that the token exists, is unexpired, matches policy for the intended cluster, and has not already been consumed. The gateway then evaluates `AgentApprovalPolicy`. The default policy is permissive for valid tokens, but the hook exists for human approval or other risk controls. This mirrors OCM’s double-opt-in approach: the managed side asks to join, the hub side explicitly accepts.

Once approved, the gateway issues a short-lived client certificate, default 24 hours. The certificate carries the assigned `agent_id` in SAN form. The gateway’s internal CA signs it, and the gateway returns both the signed cert and the CA bundle. The agent persists them and uses them for future `Connect` calls. The CSR subject can carry operator-friendly hints, but it is not the source of truth for identity. The source of truth is the gateway-assigned `agent_id` plus the fingerprint bound to it.

Rotation follows a renew-at-50% rule. When half of the current certificate TTL has elapsed, the agent initiates renewal over mTLS using its still-valid certificate. Renewal proves possession of the current identity, receives a new cert, and leaves the old cert valid until natural expiry. That overlap avoids breaking in-flight operations during rollover and prevents race conditions where a new cert invalidates an active connection mid-run.

Revocation is explicit and immediate. The gateway can push `RevocationNotice` to connected agents, but the authoritative control is server-side: a denylist of revoked fingerprints and agent IDs. A denied agent cannot reconnect even if its certificate has not yet expired. All outstanding sessions for that agent are invalidated immediately; they do not linger until a lease timeout. This is the only safe response to suspected compromise.

Replay protection is monotonic nonce-based. Every `AgentEnvelope` carries a per-agent nonce and a signature over the canonical envelope hash. The gateway stores the highest nonce seen for each `agent_id` and rejects any envelope whose nonce is less than or equal to that value. The agent must persist its nonce counter across restarts. If it loses that counter, it has effectively lost the ability to prove freshness and should re-enroll rather than guessing.
