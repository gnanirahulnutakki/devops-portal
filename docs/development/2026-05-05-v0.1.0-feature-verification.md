# v0.1.0 Feature Verification Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to walk this plan task-by-task. Each task has a verification step and a contingent fix step. Pass = check the box and move on. Fail = file the issue, fix, re-verify, commit.

**Goal:** Walk every README-claimed feature against a live environment, document what works and what doesn't, fix the blockers, and produce a v0.1.1 patch release with all critical findings resolved.

**Architecture:** Test-first verification against a real kind cluster + helm-installed platform services (ArgoCD, Prometheus, Grafana, Loki). No mocks. Every fix gets a real commit; every test gets a real assertion. Pipeline gates (typecheck, lint, vitest) are the floor; UI walkthroughs and HTTP probes are the body.

**Tech Stack:** Next.js 15 (running locally), Postgres 16, Redis 7 (in docker-compose), kind cluster `portal-demo`, kubectl, helm, gh CLI for issue filing.

**Baseline (verified at plan-write time):**
- Portal: `http://localhost:3000` healthy, version 0.1.0
- DB: `postgres@5432` healthy, latency 1ms
- Redis: `redis@6379` healthy (queue disabled — that's the default)
- Kind cluster: `portal-demo` exists with `demo-app` namespace pre-populated
- Admin: `admin@example.com` / `admin123` (seed-created)
- Org id: `cmoqb1j0g0000s12o3s0u18im` (Default Organization)
- Registered cluster: "Kind Portal Demo" (id `cmoqbw2tg0001s1pjilpbyear`)

**Out of scope for this round** (gated on real external services, deferred to v0.2 / v0.5):
- Keycloak SSO (no Keycloak running)
- GitHub OAuth (no GitHub OAuth app)
- Azure AD / Google OAuth
- Uptime Kuma integration (no Kuma instance)
- Vulnerability / Trivy Operator (not installed in kind)
- MCP / LLM assistant (no Ollama / external LLM)
- DORA Metrics page (no GitHub events feeding it)
- Scorecards live evaluation (depends on ArgoCD + Grafana)
